## 项目目录与本机配置

根目录为包含 README.md、backend、frontend、android、compose.dev.yaml 的 PuppleTrouble 目录，不要求组员采用同一绝对路径。所有相对命令从根目录开始，遇到 Set-Location 后以切换后路径为准。

运行 `scripts/setup-local.ps1` 可生成不覆盖已有文件的本机配置。根目录 .env 具有随机开发密码；不复用其他项目的密码或数据库；端口如有冲突，按下文方案调整。

| 位置／变量 | 用途 |
|---|---|
| 根目录 .env：APP_ENV、DATABASE_URL | 运行环境及真实数据库连接；主机地址 127.0.0.1:5678 |
| POSTGRES_DB／USER／PASSWORD | 本项目开发数据库 puppletrouble；密码只保存在本机 |
| JWT_SECRET、STORAGE_DIR | 服务端签名秘密及私有存储位置；业务认证／上传尚未实现 |
| MAX_UPLOAD_MB／MAX_IMAGE_PIXELS | 后续图像输入限制，当前只是配置预留 |
| MODEL_API_KEY／MODEL_API_BASE_URL／MODEL_NAME、AI_MODE | 未来真实模型接入；密钥只在服务端，当前无调整接口 |
| CORS_ORIGINS、ALLOW_DEV_HTTP | 明确允许开发来源；生产禁用开发 HTTP 与模拟配置 |
| frontend/.env.local：VITE_API_BASE_URL | 浏览器可见的 API 地址，不含秘密 |
| android/local.properties：sdk.dir／API_BASE_URL | 本机 SDK 与构建期 API 地址，禁止提交 |

后端总是从根目录 .env 显式加载；Compose 的 --env-file 不等于主机 Python 自动获得变量。STORAGE_DIR 相对路径按根目录解析。

| 组件 | 地址 |

## 前端环境配置

### 工具与依赖

安装 Node.js 22.12 以上。工程为 React 19、TypeScript 5.9、Vite 7，已有 package.json、package-lock.json、Tailwind 插件、API 客户端和首页。首次在 frontend 执行 npm ci，后续仅依赖变化时重装。

### 公开配置

在根目录运行 scripts/setup-local.ps1 生成 frontend/.env.local，或首次从 frontend/.env.example 复制。默认 `VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1`。Vite 变量进入浏览器，不能放模型 key、JWT_SECRET 或数据库密码。

### 运行和检查

从根目录进入 frontend：

```powershell
Set-Location frontend
npm ci
npm run dev
```

浏览 http://127.0.0.1:5173 ，连接已运行后端时显示连接正常。5173 被占用会报错，不自动换端口。修改 Vite 环境变量后重启。`npm run build` 做类型检查并输出 dist；`npm run preview` 在 4173 预览构建。

`npm run test` 验证断连时的恢复提示；`npm run test:e2e` 要求后端运行，运行前需安装 Microsoft Edge，或调整 Playwright 的 channel 并安装相应浏览器。当前只有启动页面，产品功能文件已预留但为空。

### 跨域与发布

后端 CORS_ORIGINS 允许 localhost／127.0.0.1:5173 及本地构建预览的 4173。生产构建建议 VITE_API_BASE_URL=/api/v1，并由静态服务器代理同域 API。Vite dev server 不用于生产。

后续认证图片使用带权限请求获取 Blob 等受控方式，不将私人图片公开来绕过跨域；导出前等待字体／图像加载。当前 PNG 导出尚未实现。

## 后端环境配置

### Python 环境

使用 Python 3.12，在根目录创建 .venv。当前有 FastAPI 应用、配置、数据库会话、统一响应／错误、请求标识、CORS 和运行检查。无需重新生成入口。

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
```

python 必须指向 3.12，否则先安装 Python 3.12，再使用其解释器路径或 py -3.12 创建。requirements.txt 为直接依赖范围，requirements.lock.txt 固定 Windows/Python 3.12 的依赖版本；其他系统需要单独验证兼容性。无需激活即可使用 .venv/Scripts/python.exe。

### 根目录配置

scripts/setup-local.ps1 首次生成根目录 .env，已有文件不覆盖。服务不依赖当前终端路径，总是显式读取根目录配置；Compose 不会自动注入主机 Python。DATABASE_URL 及随机密码由脚本成对填写，JWT_SECRET 仅保存在本机。

APP_ENV 限 development/test/production；AI_MODE 限 real/mock。当前模型业务尚未接入；生产校验会拒绝模拟模式、开发 HTTP 和无效签名密钥，不代表已具备完整生产鉴权。

### 启动与测试

数据库启动后，从根目录执行：

```powershell
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
Set-Location backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

health 在 /api/v1/health，数据库就绪检查在 /api/v1/health/ready，交互文档在 /docs。未实现的业务空文件不注册接口。修改 .env 后手动重启服务。

根目录测试：`.\.venv\Scripts\python.exe -m pytest -c backend/pytest.ini`。统一错误不回显密码／连接串，CORS 来源须匹配实际 Web 地址。局域网真机确有需要时再显式扩大监听并限制防火墙，默认用本机监听和 USB reverse。

## 数据库环境配置

### 参数

运行 Docker Desktop 和 Compose。项目使用 postgres:16，主机绑定 127.0.0.1:5678，容器内 PostgreSQL 也监听 5678；库名和用户名默认均为 puppletrouble，密码由 scripts/setup-local.ps1 在根目录 .env 中随机生成。不要复用其他项目的数据库或已有账号。

主机上的后端使用 DATABASE_URL 中的 127.0.0.1；只有未来后端也进入同一 Compose 网络才使用服务名 db。目前 Compose 只有 db 服务。私人密码不写进文档或 Git。

### 启动与迁移

从根目录执行：

```powershell
docker compose --env-file .env -f compose.dev.yaml config --quiet
docker compose --env-file .env -f compose.dev.yaml up -d --wait db
docker compose --env-file .env -f compose.dev.yaml ps
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini current
```

等待 db 为 healthy 再迁移。当前只有 0001_initial_users，创建 users 结构，不导入账号或作品。后续新迁移按模型变更生成，不在扫描目录放空迁移。检查 /api/v1/health/ready 是否 ready，不只看容器进程存在。

### 保留数据与排障

日常停止用 `docker compose --env-file .env -f compose.dev.yaml stop db`。down 默认保留命名卷，不随意添加 -v。改 .env 密码不会更新旧卷账号，需先备份并用数据库命令修改；端口冲突先确认占用用途，改映射时同步 DATABASE_URL。

日志使用 `docker compose --env-file .env -f compose.dev.yaml logs --tail 50 db`，去敏后再分享。计划中的 backup-db.ps1／restore-db.ps1 目前为空，尚不能用于备份或恢复；正式实现与验证安排在 D21 前。

## 算法与 AI 环境配置

### 图像依赖

安装 backend/requirements.lock.txt 包含 Pillow、OpenCV、NumPy、colour-science、scikit-learn。业务算法文件当前为空；安装库不代表已经实现取色、蒙版、配色迁移或评测。不另建公开 API、数据库或独立 Python 环境。

图像处理将按方向／ICC／sRGB／透明背景统一，再进行确定性取色与蒙版计算。输入记录许可与来源，私人上传不提交；样例记录参数、图像版本、算法版本、输出和误例。

### 模型配置

MODEL_API_KEY、MODEL_API_BASE_URL、MODEL_NAME 只在根目录 .env 的服务端使用。当前无需 key 即可启动框架；后续接真实模型再填入自己的配置，并改 AI_MODE=real。密钥不得进入 VITE_ 变量或 Android 安装包。

AI 适配、意图与解释文件已预留为空，当前没有真实或模拟调整接口。未来 mock 必须在结果和 UI 明示，规则备用也不得伪装成模型结果。模型输出需经过 schema、色值、锁定、来源和版本校验，用户确认后才能保存。

### 后续验证

计划 D12 前提供真实模型局部调整记录，D21 前固定样例与复现入口；尚未建立的算法命令不列为可运行命令。Jupyter 仅探索，正式交付可独立执行模块，不能依赖 Notebook 隐藏状态。

## 移动端环境配置

### Android Studio 是什么

Android Studio 是 Android 官方开发工具，相当于为 Android 开发准备的代码编辑、构建、调试和设备管理工作台。它用于编写 Kotlin／Compose 界面、管理 SDK、通过 Gradle 构建 APK、启动模拟器、向手机安装 App 以及查看 Logcat 日志；它不是数据库，也不负责运行 Web 或后端。

主要由移动端成员使用，其他成员只验证 Web／后端时无需安装。已具备 JDK、SDK 和 Wrapper 时可用命令行构建，但 Android Studio 对界面调试和设备管理更方便。依据：[Android 官方介绍](https://developer.android.com/studio/intro)。

### 固定工具链

Android 原生 Kotlin／Compose 工程已建立。Gradle Wrapper 8.14、AGP 8.13.1、Kotlin／Compose Compiler 插件 2.2.20；构建使用 JDK 21，输出 Java 17 字节码。compileSdk/targetSdk=36，minSdk=26；安装 SDK Platform 36、Build Tools 35.0.0 和 Platform Tools。

具体库版本在 android/gradle/libs.versions.toml；无需安装全局 Gradle。兼容依据见[Android 官方 AGP 说明](https://developer.android.com/build/releases/agp-8-13-0-release-notes)，Compose Compiler 与 Kotlin 插件使用同一版本。

### 本机配置

从根目录执行 scripts/setup-local.ps1，找不到 SDK 时通过 -AndroidSdk 指定自己的安装目录。脚本写 android/local.properties 的 sdk.dir（斜杠格式）和默认模拟器 API 地址，不覆盖已有配置。

```properties
API_BASE_URL=http://10.0.2.2:8000/api/v1/
```

Gradle 在构建时显式读入地址，修改后必须重建。模拟器 10.0.2.2 指向电脑；USB 真机用 adb reverse 后改为 127.0.0.1。HTTP 仅 debug 开启，release 要求显式 HTTPS 地址。SDK 路径、签名和秘密不提交。

### 运行

Android Studio 打开 android，同步并选择 JDK 21；Device Manager 创建／启动 AVD，或者连接已授权 USB 调试的手机。启动后端后点击 Run；命令行从 android 执行 `.\gradlew.bat :app:assembleDebug` 和 `:app:installDebug`，然后打开“玩犊紫”。APK 为 app/build/outputs/apk/debug/app-debug.apk。

首页是真实健康请求、超时提示与重试；相册、模板、项目和本地业务缓存尚未实现。产品 Screen／ViewModel／Repository 文件为空，后续按 Sprint 实现。当前没有 Android 单元测试源码，testDebugUnitTest 的 NO-SOURCE 不算测试通过。

模拟器安装和启动验证不代替后续实体机产品验收。连接失败核对 API 地址、重建、debug 网络策略、reverse、后端监听；不要把服务端密钥放入 App 绕过服务。

## 数据库连接与端口调整方案

### 连接方式

PostgreSQL 是数据库服务，需先启动 db 再用客户端连接。项目不附带数据库图形界面。

| 参数 | 配置 |
|---|---|
| 主机 | `127.0.0.1` |
| 主机端口 | `5678` |
| 容器内端口 | `5678` |
| 库名／用户名 | 默认均为 `puppletrouble`，以根目录 `.env` 为准 |
| 密码 | 根目录 `.env` 的 POSTGRES_PASSWORD |

可使用支持 PostgreSQL 的图形客户端，或使用容器自带的 psql：

```powershell
docker compose --env-file .env -f compose.dev.yaml exec db psql -p 5678 -U puppletrouble -d puppletrouble
```

进入后 `\dt` 查看表，`\d users` 查看结构，`\q` 退出。自定义用户名或库名后需替换命令参数。容器内连接不能代替主机连接验证；后端通过 DATABASE_URL 连接，以 `/api/v1/health/ready` 检查就绪状态。

### 端口配置

| 位置 | 配置 |
|---|---|
| Compose command | `postgres -p 5678`，设置 PostgreSQL 实际监听端口 |
| Compose ports | `127.0.0.1:5678:5678`，主机与容器端口一致，仅开放回环地址 |
| Compose healthcheck | `pg_isready -p 5678`，连接实际端口 |
| 根目录 `.env` 的 DATABASE_URL | 使用 `@127.0.0.1:5678/` |
| 图形客户端／psql | 明确填写端口 `5678` |
| Web／Android | 连接后端 HTTP API，不直接连接数据库 |

若 5678 被其他服务占用，先确认占用用途；需要更换时同步修改 command、ports、healthcheck 和 DATABASE_URL，重新应用 Compose 配置并重启后端。不同成员各自电脑使用相同端口互不冲突。端口变更无需重建数据卷或修改表结构。

### 默认账号及如何配置

| 类型 | 目前值／状态 |
|---|---|
| 数据库名 | `puppletrouble`，对应 POSTGRES_DB |
| 数据库连接用户名 | `puppletrouble`，对应 POSTGRES_USER；不是固定的 postgres 用户名 |
| 数据库密码 | 首次执行 setup-local.ps1 时随机生成，保存在本机 `.env` 的 POSTGRES_PASSWORD，不在文档或 Git 中公开 |
| 后端连接串 | DATABASE_URL，必须与上面的用户名、密码、数据库及主机端口一致 |
| 应用登录账号 | 当前没有默认账号，也未实现注册／登录；users 表存在不代表已有用户 |

首次初始化前，可以在本机 `.env` 设置上述参数，再启动 db；不要使用 `.env.example` 的占位密码。密码含 URL 特殊字符时，DATABASE_URL 中的密码部分需做 URL 编码；生成脚本使用随机十六进制密码可避免这类问题。

已有数据卷时，修改 `.env` 不会自动修改库内账号或密码。应先确认备份可用，再通过 PostgreSQL 修改角色密码／权限并同步本机连接参数；不能为改密码直接删除卷。官方镜像的 POSTGRES_USER／PASSWORD 只在空数据目录首次初始化时生效。依据：[Docker PostgreSQL 数据持久化说明](https://docs.docker.com/guides/postgresql/immediate-setup-and-data-persistence/)。

当前 POSTGRES_USER 由开发镜像创建为初始化管理角色，适合隔离的本机开发环境；正式部署再拆分迁移管理角色与最小权限的应用角色。

### 为什么没有数据库文件夹

| 内容 | 实际位置 |
|---|---|
| 服务与持久化声明 | 根目录 `compose.dev.yaml` |
| 连接与会话 | `backend/app/core/database.py` |
| 已实现 users 表模型 | `backend/app/modules/auth/models.py` |
| 数据库迁移 | `backend/alembic/` 和 `backend/alembic.ini` |
| 实际数据库数据 | Docker 管理的命名卷；默认名 `puppletrouble-dev_postgres_data`，容器内目录 `/var/lib/postgresql/data` |
| 设计与规划 | [数据库设计](数据库设计.md) |

数据库数据由 Docker 保存，不放在源码目录，不提交 Git，也不以普通复制目录代替数据库备份。当前只有 users 和 Alembic 版本表，其余表尚在设计阶段。无需为了目录完整而新建一个空 database 目录。

## 本地工具与可清理文件

| 文件／目录 | 处理原则 |
|---|---|
| `.venv/Scripts/*.exe`、pip 自带启动器 | Python、pip、迁移及测试的运行工具；保留，不上传 |
| `frontend/node_modules` 中的 exe／ps1 | Web 依赖及命令入口，例如 esbuild；保留，不上传 |
| `scripts/setup-local.ps1` | 项目维护的配置脚本，是源码，保留并提交 |
| 预留备份／恢复 ps1 | 按开发计划保留的空文件，不能作为已实现工具使用 |
| `android/gradlew`、`gradlew.bat`、Wrapper JAR | 固定构建工具版本所需，保留并提交 |
| `__pycache__`、pyc、dist、build、测试输出、项目级 `.gradle` | 可重新生成的缓存／产物，可在不构建时清理；不上传 |

`.ps1` 是 PowerShell 脚本，扩展名本身不能用于判断是否为编译产物。删除依赖环境中的可执行工具再重新安装只会重新生成它们，不能作为保持工程可启动的清理方式。
