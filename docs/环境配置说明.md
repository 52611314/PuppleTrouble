# PuppleTrouble 环境配置说明

本页是环境配置入口，按前端、后端、数据库、算法与 AI、移动端分册。先阅读[HANDOFF](HANDOFF.md)了解当前状态，启动顺序见[项目启动](项目启动.md)，协作与同步见[项目协作](项目协作.md)。**各分册命令均默认从仓库根目录执行，而非文档所在目录。**

当前仅有环境样例、数据库 Compose 与后端依赖候选清单。Web、Android、业务入口、迁移尚未建立；不能执行依赖这些工程的命令，也不宣称依赖已锁定或全栈已启动。

## 2 共用准备

安装 Git；根据分工安装各分册工具，无须每个人安装全部开发工具。涉及本地数据库时需要运行中的 Docker Desktop／Compose。技术选型见[技术栈说明](技术栈说明.md)，初始化时固定实际验证过的版本。

根目录配置仅首次复制，已有 `.env` 不覆盖：

```powershell
Copy-Item -LiteralPath .env.example -Destination .env
```

改成本机值，不提交真实 `.env`。后端必须显式从根目录加载配置；Compose 的 `--env-file` 不会自动给主机上的 Python 注入变量。相对 STORAGE_DIR 按根目录解析。前端使用自己的公开配置，Android 使用本机地址配置，均不能携带服务端密钥。

## 3 配置归属

| 位置／变量 | 管理者 | 说明 |
|---|---|---|
| 根目录 `.env`：APP_ENV | A/B | development/test/production；生产不启用模拟模式 |
| POSTGRES_DB/USER/PASSWORD、DATABASE_URL | B | 密码需一致；URL 特殊字符编码；本机主机用 127.0.0.1 |
| JWT_SECRET、STORAGE_DIR | A/B | 随机签名密钥、私有存储；不进入客户端或日志 |
| MAX_UPLOAD_MB、MAX_IMAGE_PIXELS | B/C | 限制实际文件大小与解码像素，由服务端校验 |
| MODEL_API_KEY／MODEL_API_BASE_URL／MODEL_NAME、AI_MODE | C/B | 仅服务端；real 才调用真实模型，开发 mock 必须标识 |
| CORS_ORIGINS、ALLOW_DEV_HTTP | A/B | 明确允许开发来源；发布使用 HTTPS |
| `frontend/.env.local`：VITE_API_BASE_URL | A | 公开的业务 API 地址，不含秘密 |
| `android/local.properties`：API_BASE_URL | D | 本机 SDK 路径及 API 地址，不提交本机配置 |

## 4 本地联调地址和顺序

| 组件 | 地址 | 说明 |
|---|---|---|
| 数据库 | 127.0.0.1:5432 | 仅本机开发，不直连客户端 |
| 后端 | http://127.0.0.1:8000/api/v1 | A 建公共框架，B/C 实现业务及算法后可用 |
| API 文档 | http://127.0.0.1:8000/docs | 后端建立后生成 |
| Web | http://localhost:5173 | 端口变化需同步 CORS |
| Android 模拟器访问电脑 | http://10.0.2.2:8000/api/v1/ | 模拟器的 localhost 是模拟器本身 |
| USB 真机反向转发 | http://127.0.0.1:8000/api/v1/ | 先执行 adb reverse，详见移动分册 |

完整顺序为数据库→后端→Web／Android。当前仅可准备依赖和数据库；其余命令须等代码落地。首次可运行后各负责人从新环境复跑，更新分册、[项目启动](项目启动.md)和 HANDOFF，注明真实版本与验证日期。
