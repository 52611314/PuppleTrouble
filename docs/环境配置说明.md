# PuppleTrouble 环境配置说明

完整启动顺序见[项目启动](项目启动.md)，Git 同步见[项目协作](项目协作.md)。本页中的命令以仓库根目录为起点。

当前仓库处于文档准备阶段。已有 `.env.example`、开发数据库 Compose 和后端依赖候选清单；没有 Web 工程、Android 工程、业务后端入口、迁移文件或安装包。下文明确区分现在可执行的环境准备与代码建立后才可执行的步骤。

## 安装工具

- Git、稳定 Android Studio、Android SDK 与模拟器；准备一台实体 Android 手机。
- Python 3.12、Docker Desktop（启用 Compose）。JDK 与 AGP 兼容性按《技术栈说明》初始化后固定。
- Web：Node.js 22 LTS（至少 22.12）及 npm。Android 初始 SDK 目标为 36，minSdk 26。

## 现在可进行的准备

在仓库根目录的 PowerShell 执行：

```powershell
Copy-Item -LiteralPath .env.example -Destination .env
```

编辑 `.env`：将数据库开发密码改为本地值；`DATABASE_URL` 使用对应密码，特殊字符须 URL 编码。`JWT_SECRET` 生成随机值，例如 `python -c "import secrets; print(secrets.token_urlsafe(48))"`，只写入本机 `.env`。模型参数可暂留空，必须在服务器调用真实模型前填写。

```powershell
docker compose --env-file .env -f compose.dev.yaml config --quiet
docker compose --env-file .env -f compose.dev.yaml up -d db
docker compose --env-file .env -f compose.dev.yaml ps
```

数据库仅绑定本机 `127.0.0.1:5432`，用于本地开发。`docker compose ... down` 可停止容器；不要随意加 `-v` 删除数据卷。更换 `.env` 中密码不会自动改变已初始化的数据卷账户，需使用数据库命令修改或在明确保留数据后重建。

可提前创建依赖验证环境：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

依赖范围尚未解析验证；解析成功并完成兼容性检查后生成锁文件再提交。模型 key、JWT secret 和真实 `.env` 一律不提交。

## 配置项

| 变量 | 说明 |
|---|---|
| APP_ENV | development/test/production，不能在生产启用模拟模式 |
| POSTGRES_DB/USER/PASSWORD | 开发数据库参数 |
| DATABASE_URL | 主机运行后端时连接 127.0.0.1；未来后端容器中才改为服务名 db |
| JWT_SECRET | 服务端签名密钥；不得进入客户端 |
| MODEL_API_KEY / MODEL_API_BASE_URL / MODEL_NAME | 具体供应商控制台确认的密钥、兼容 API 地址和模型标识 |
| AI_MODE | real 或 mock；mock 仅开发，并在任务结果和 UI 明示 |
| STORAGE_DIR | 上传及导出的私有本地存储位置，不作为静态公共目录 |
| MAX_UPLOAD_MB/MAX_IMAGE_PIXELS | 限制文件字节和解码像素，后端验证实际文件内容 |
| ALLOW_DEV_HTTP | 仅本地开发明文访问；发布构建使用 HTTPS |

代码应由后端设置模块从根目录 `.env` 显式加载；Compose 的 `--env-file` 不等于给主机 Python 自动注入环境。相对 STORAGE_DIR 按仓库根目录解析。

## 代码建立后才能执行的步骤

B 建立 `backend/app/main.py`、设置模块和 Alembic 迁移后，才可以执行：

```powershell
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

根目录加载配置、访问权限和防火墙范围必须先完成；不要将开发服务直接暴露到公网。业务实现后检查 `/api/v1/health` 和 `/docs`，以实际响应为准。

D 建立 `android/` 工程并提交 Wrapper 后，使用 Android Studio 打开该目录；在本机 `local.properties` 保存 SDK 路径和开发 API 地址，由 Gradle 转换为构建配置。

```properties
API_BASE_URL=http://10.0.2.2:8000/api/v1/
```

Android 模拟器使用 `10.0.2.2` 访问电脑；真机可使用 USB `adb reverse tcp:8000 tcp:8000` 后访问 `http://127.0.0.1:8000/api/v1/`，或明确配置同一局域网地址。`adb reverse` 只适用于连线调试。明文 HTTP 只通过 debug 配置放行；release 必须 HTTPS。

工程建立后，从 `android/` 执行 `./gradlew.bat assembleDebug`；后端测试从根目录执行 `.venv/Scripts/python.exe -m pytest backend/tests`。这些路径目前是计划，尚不能运行。

## Web 工程建立后的配置

A 建立 `frontend/` React + TypeScript + Vite 工程并提交 package-lock.json 后，进入该目录执行 `npm ci`、`npm run dev`；构建、单元测试和端到端分别约定 `npm run build`、`npm run test`、`npm run test:e2e`。当前没有 package.json，这些命令尚不可运行。

复制 `frontend/.env.example` 为 `frontend/.env.local`。Vite 环境变量进入浏览器构建，仅允许公开配置，例如 `VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1`；不得放模型 key 或 JWT secret。

本地 Web 源为 http://localhost:5173 或 http://127.0.0.1:5173，后端只允许明确配置的 CORS_ORIGINS。生产建议反向代理到同域 `/api/v1`，部署时打包设置 VITE_API_BASE_URL=/api/v1。Vite 开发服务不是生产服务器。

浏览器访问认证图片时先 fetch 获取 Blob 再展示，或实现严格受控的图片响应；不要为绕过跨域把用户素材公开。导出使用的字体和图片应可合法访问并等待载入，防止 Canvas 被跨域资源污染而无法导出。

## 常见问题

- 端口占用：改 Compose 映射端口，并同步 DATABASE_URL。
- 真机请求失败：核对地址、USB reverse、debug 网络策略和防火墙，不能把模型 key 放到客户端绕过服务。
- 颜色不一致：核对图像 ICC、sRGB、透明背景、显示设备和预览渲染；不以截图压缩后的像素证明原始色号。
- 模型格式错误：服务端校验失败并返回明确错误，保存旧项目；可测试 mock，但不能展示为真实 AI。
- 配置泄露：立即轮换密钥并检查历史；仅加入 `.gitignore` 无法清理已提交的秘密。
