# 后端环境配置

A 主责公共框架，B 主责业务／数据库接入，C 共用环境开发算法。返回[环境配置入口](../环境配置说明.md)，启动顺序见[项目启动](../项目启动.md)。命令从仓库根目录执行，修改前先阅读[HANDOFF](../HANDOFF.md)。

## Python 与依赖准备

安装 Python 3.12。可先建立隔离环境并解析候选依赖：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

requirements.txt 是未锁定的直接依赖范围，不保证已通过兼容性检查。周期 1 由 B 结合 C 的图像依赖解析并生成实际验证后的锁定结果，再补充锁定安装方式；不提前声称可复现应用构建。后续复用已有 venv，无需重复创建。

## 服务端配置

首次复制根目录 `.env.example` 为 `.env`。DATABASE_URL 见[数据库分册](数据库.md)；修改数据库密码时保持一致。JWT_SECRET 可在本机生成：

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

仅把结果写入本机 `.env`，不贴到交接或日志。A 的设置模块应显式从根目录加载 `.env`，不能依赖 Compose 自动注入主机进程；相对 STORAGE_DIR 按根目录解析，上传文件不作为公共静态目录。

APP_ENV、上传限制、CORS_ORIGINS 和 ALLOW_DEV_HTTP 由设置模块校验。开发 Web 来源一般为 localhost／127.0.0.1:5173，发布用 HTTPS。模型参数仅在服务端，见[算法与 AI](算法与AI.md)。

## 后端工程建立后

前置条件：A 已提交 backend/app/main.py、配置和公共路由框架，B 已提交数据库模型、迁移与业务实现，数据库可连接。当前缺少这些代码，以下命令暂不可执行：

```powershell
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

迁移前核对数据库目标。业务建立后检查 `/api/v1/health`、`/docs` 及实际鉴权业务，health 成功不等于 AI／资料库全部可用。C 的模块在同一服务加载，不另起公开接口。

后端测试约定从根目录执行 `.\.venv\Scripts\python.exe -m pytest backend/tests`；待测试代码和配置提交后才可运行。覆盖接口、权限、版本事务、任务状态及算法约束，补充真实记录。

## 常见问题

- 找不到 app.main：检查当前是否仍为文档阶段，不建立假入口来掩盖业务缺失。
- 数据库认证失败：核对 URL 编码、密码和已有数据卷账户，详见数据库分册。
- 跨域失败：核对真实 Web 来源与 CORS_ORIGINS，而非放开全部私人资源。
- 局域网真机确有需求时才扩大监听范围并限制防火墙；默认仅绑定本机。

验收记录：当前只提供候选依赖及配置约定，未验证业务启动或迁移。
