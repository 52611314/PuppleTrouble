# PuppleTrouble 项目开发计划

人员 4 人，2026 年 11 月 15 日开工，2026 年 12 月 14 日交付，共 30 个自然日，日期均为北京时间。开发前的文档准备不计入工期。

**每 3 天一个周期，共 10 个周期；前 7 个周期（D1～D21，至 12 月 5 日）完成基础版本，后 3 个周期用于稳定、验证和交付。** 本表是计划，不代表已完成开发。每个周期按任务包推进，不再重复列出每天的同类工作。

启动时确认各人可投入时间；如课程等影响进度，先减少辅助功能和素材扩充，不将基础功能推迟到第 22 天以后。区域初赛截止为 2027-01-15 18:00，本计划不把此后完善时间算作默认工期。

## 1 基础版本范围与交付节点

核心闭环：浏览颜色 → 查看真实作品中的颜色区域和解释 → 应用到单页模板 → 自然语言局部修改 → 锁定与撤销 → 保存和复用项目风格 → 导出。

| 优先级 | 范围 | 完成要求 |
|---|---|---|
| P0 | 色系浏览、色号、作品详情和颜色高亮 | 可重复取色；来源可追溯；高亮阈值可调整 |
| P0 | 颜色角色映射、2～3 个结构化模板、候选预览 | 背景、正文、强调色清晰；可比较、锁定、撤销 |
| P0 | AI 理解与局部配色修改 | 真实模型调用经过校验；保留锁定项；失败不破坏项目 |
| P0 | 收藏、项目版本、偏好范围、PNG/JSON 导出 | 可重新登录恢复；账户隔离；旧版本可回看；Web 完整编辑、Android 轻量调整 |
| P0 | 可复跑的基础发布包 | Web 构建、可安装 APK、可部署 API、迁移与种子命令、启动说明及已知限制 |
| P1 | 风格筛选、相近色、更多作品、简易图表配色 | D21 基础版通过后，有余量再选择；不占用缺陷修复和测试时间 |
| P2 | 更多字体形状建议、CSS 导出 | 可递延，不计入基础版完成条件 |

精选作品先保证约 20 件来源审核通过的资料；40～60 件为扩充目标，不是 D21 硬门槛。首版不加入任意 PPTX 往返编辑、通用网页编辑器、印刷校色或自训练大模型。

## 2 职责和固定工作方式

| 成员 | 主责与模块约定 | 固定交接物 |
|---|---|---|
| A | Web；兼后端架构、应用入口、统一配置／错误处理／路由框架及接口契约设计 | frontend 页面与画布；backend 框架变更；架构图、接口样例、Web 验证 |
| B | 后端业务与数据库：API、账户权限、上传、项目版本、任务持久化、迁移及部署 | backend 的业务、模型、迁移；请求响应、权限和恢复验证 |
| C | 后端算法与 AI：图像处理、蒙版、候选、意图、解释、约束与资料库 | algorithms／ai／knowledge；可重复样例、算法版本、来源台账和误例 |
| D | Android；兼每 6 天组织一次联合测试 | android 页面、预览与 APK；真机记录、联合测试清单与缺陷汇总 |

以上代码目录均为待建约定。A/B 共同确认架构与契约，A 实现公共框架，B 在该框架下实现业务并维护 API 发布与数据库；C 提供内部模块，不另建 API 或数据库。A 在首周期集中完成框架，后续以接口评审和必要修正为主，保证 Web 主责投入。具体边界见[分工安排](分工安排.md)。

各成员每天自行验证改动，重复的自测、同步、文档维护不再逐日列入日程。每次修改前阅读[HANDOFF](HANDOFF.md)，修改后更新交接记录并同批提交；周期末提交任务结果、实际验证、遗留问题和下一周期依赖。

## 3 三天周期任务

每周期开始确认输入与任务归属，周期内实现并联调，周期末按下述条件演示。下列“交付”均须有对应提交、可运行样例或文档证据；未完成项写入 HANDOFF，不以代码已写完代替验收。

### 周期 1｜D1～D3｜11 月 15 日～11 月 17 日：统一架构和工程骨架

| 成员 | 本周期任务与交付 |
|---|---|
| A | 初始化 React/TS/Vite、导航和颜色卡；建立 Konva 模板样例。兼建 FastAPI 应用入口、根目录配置加载、统一错误响应、路由前缀和 health；与 B 冻结第一版契约及角色／模板 schema。 |
| B | 建 SQLAlchemy/Alembic 与首批用户、作品、素材、项目模型；实现注册登录及资源所有权骨架；接入 A 的框架，解析并锁定后端依赖。 |

## 5 依赖、反馈和质量要求

- 接口与模板输入：A/B 的框架和契约→B/C 的真实数据／蒙版／候选→A/D 展示；版本保存统一经过 B 的服务。接口未就绪时可用带 mock 标识的固定样例，从 D9 起核心节点必须真实联通。
- 依赖延期：先完成不依赖它的界面状态、契约验证或误例整理；HANDOFF 写明缺口和接手人，A 协调范围。先递延 P2/P1、素材扩充与额外模板，不删核心验证。
- 用户反馈：正式访谈与试用从 D15 左右开始，观察任务完成时间、有效修改次数、参考配色应用及解释理解；保留同意、原始问题与修改记录，审美偏好不包装成客观总分。
- 验证范围：颜色匹配、锁定不变、候选不自动保存、版本冲突、撤销、模型失败、账户隔离；至少一台实体 Android 手机，桌面 Chrome/Edge 验证画布与导出。
- 数据与诚实性：记录真实延迟、上传量、资源与调用成本；无密钥、个人资料、未授权素材入库。规则备用明确标识，AI 不稳定不能伪称已完成；文档检查不等于应用测试通过。
