# PuppleTrouble 四人分工安排

成员姓名由队长补充，A 暂记为队长；如队长承担其他岗位，只调整统筹职责。总体为一人主责 Web、两人主责后端、一人主责移动端；A 兼后端架构和接口框架，D 兼每六天一次的联合测试组织。所有成员负责自己模块的日常自测与文档。

| 成员 | 岗位 | 主要职责 | 文档与证据 |
|---|---|---|---|
| A | Web 前端，兼架构／后端公共框架 | React 页面、颜色探索、作品展示、Konva 画布、候选对比、锁定撤销、收藏项目、Web 导出；后端分层、应用入口、配置加载、路由组织、统一错误响应与接口契约；产品统筹 | 原型、架构图、公共接口样例、项目计划、Web 验证、试用及演示 |
| B | 后端兼数据库 | 基于公共框架实现业务 API、账户权限、上传存储、PostgreSQL 建模迁移、项目版本与事务、任务持久化、部署和恢复 | 接口实现说明、环境与数据库说明、迁移恢复记录、接口和权限测试 |
| C | 后端兼算法 | 图像归一化、取色、色差蒙版、区域统计、配色关系、AI 意图与解释、知识检索和约束校验 | 技术研究、算法评测、AI 轨迹、作品来源与授权台账 |
| D | Android 移动端，兼测试协调 | 原生颜色浏览、拍照／相册、作品高亮、模板预览、轻量调整、收藏复用、真机和 APK；每六天组织一次跨模块测试 | 移动说明、兼容性／性能记录、APK；联合测试清单、缺陷汇总与复测记录 |

## 架构、接口与模块边界

| 内容 | 主责 | 配合与边界 |
|---|---|---|
| 服务分层、模块依赖、应用入口、配置和统一响应 | A | B 评审并接入业务；A 首周期集中实现，此后负责必要修正，不包办全部后端 |
| API 路径、请求响应、错误码、版本／任务约定、模板 schema | A 牵头设计，B 共同确认 | B 维护业务契约、OpenAPI 与接口发布一致性；C/D 确认算法及移动需求；变更同步文档与 HANDOFF |
| 业务服务、认证与资源权限、数据模型／迁移／事务 | B | A 评审接口边界；C 调用统一业务能力，不直接写用户项目版本 |
| 算法、模型适配、候选及约束校验 | C | B 负责业务调用和任务持久化；A/D 展示结果，不在客户端存模型密钥 |
| Web 完整编辑及 Android 轻量预览 | A／D 各自负责 | 共用颜色角色、模板 schema、样例及服务端版本，不另建一套 API／数据库 |
| 每六天联合测试 | D 组织 | 四人参与，缺陷由模块负责人修复；日常测试仍由各成员随开发完成 |

A/B 不重复建立后端骨架：公共框架由 A 主改，业务／数据库由 B 主改，共同文件修改前在 HANDOFF 标明范围。B/C 共同维护任务调度、缓存键与失败行为；候选只有在用户确认后才经业务服务保存。

作品图像与蒙版由 C 生成、B 管权限，两端按同一 image_version 使用。A 主责完整画布，D 只为少量模板实现原生预览与角色调色；规范色值一致，字体排版的端差异单独验证。客户端账户缓存隔离，AI 候选不自动覆盖已保存内容。

## 六天测试节奏

D 在 **D6（11 月 20 日）、D12（11 月 26 日）、D18（12 月 2 日）、D24（12 月 8 日）、D30（12 月 14 日）** 组织联合测试。每轮准备样例与清单，记录环境、步骤、预期／实际结果和缺陷，分派负责人并汇总复测。具体重点见[项目开发计划](项目开发计划.md)。

D 不每天承担全组测试汇总，也不独自测试所有模块。A 验证 Web／公共框架，B 验证接口／数据库，C 验证算法／AI，D 验证移动；修复者补充证据。D21 的基础版成果验收由 A 汇总，D 提交移动交付物与已有记录，不额外增加一次 D 专项联合测试。

## 交叉评审与交接

| 主责内容 | 评审安排 |
|---|---|
| A Web | D 检查共用模型与流程，C 检查色值与解释呈现 |
| A 公共框架／契约 | B 检查可维护性、业务与数据库接入，C/D 确认消费契约 |
| B 后端数据库 | A 检查接口与架构一致性，C 检查算法调用及异常路径，D 验证移动联调 |
| C 后端算法 | B 检查隔离、超时与业务接入，A/D 检查显示效果 |
| D 移动／测试汇总 | A 检查产品一致性，B 检查网络与权限；各成员确认自己模块的测试结论 |

HANDOFF 现阶段按队长要求留空，暂不填写；恢复交接记录后，修改其他内容前先阅读[HANDOFF](HANDOFF.md)，确认最新约定、依赖和接手任务；完成修改后更新当前状态及交接记录，与功能同批提交。交接提供输入输出、样例、失败行为、真实验证、未解决问题和下一接手人。模拟结果明确标识 mock，接口约定不能只留在聊天中。

每日短同步；每六天一个 Sprint，前／后三天各核对一次成果。A 组织中后期试用，四人分析对应模块问题。每人保存去敏后的关键 AI 编程记录，评审材料使用匿名副本。

六天 Sprint 与前／后三天任务见[项目开发计划](项目开发计划.md)，Git 提交与同步见[项目协作](项目协作.md)。
