# PuppleTrouble 技术栈说明

技术基线 v0.1，2026-11-10 更新职责。当前为选型与配置约定，尚无已编译的应用。前端明确采用 React Web；移动端采用 Kotlin 原生 Android；后端采用 Python。四人主责 Web、后端与数据库、后端与算法、移动端；A 兼后端架构与接口框架，D 兼每六天一次的联合测试组织。环境配置按模块拆分，见[环境配置说明](环境配置说明.md)。

## Web 前端技术栈

Web 是完整配色工作台，移动端是独立的原生 Android 应用，共享服务端和项目模型。

| 环节 | 技术 | 职责 |
|---|---|---|
| 语言与 UI | TypeScript、React、Vite | 颜色探索、作品详情、项目编辑工作台 |
| 样式 | Tailwind CSS | 布局、主题与响应式组件；不把组件默认色冒充推荐配色 |
| 路由 | React Router | 浏览、作品、项目与编辑页面 |
| 画布 | Konva、react-konva | 结构化模板、图层选择、配色预览、对比与 PNG 导出 |
| 本地编辑状态 | Zustand | 当前草稿、锁定项和撤销／重做；提交后以服务器版本为准 |
| 服务端状态 | TanStack Query | 列表、项目、任务轮询与缓存；不承担本地撤销栈 |
| HTTP 与校验 | fetch、Zod | 令牌注入、响应解析和客户端提示；服务端仍做权威校验 |
| 测试 | Vitest、React Testing Library、Playwright | 状态、交互、端到端和画布导出 |

Node.js 22 LTS（至少 22.12）作为基线，npm 管理依赖；D1 初始化后提交 package-lock.json，使用 npm ci。React 与 react-konva 的主版本兼容性通过实际构建固定，不提前声称已验证。

参考：[Vite 环境要求](https://vite.dev/guide/)、[react-konva](https://konvajs.org/docs/react/index.html)、[TanStack Query](https://tanstack.com/query/latest/docs/framework/react/overview)。

Web 主责完整编辑；Android 主责颜色浏览、拍照／相册输入、颜色高亮、方案预览、轻量调整、保存与复用。Android 使用同一模板 schema 实现少量原生预览，不复制 Web 的完整图层排版工具。

## Android 移动端

| 环节 | 选择 | 负责能力 |
|---|---|---|
| 语言 | Kotlin | 客户端业务与图形逻辑 |
| UI | Jetpack Compose、Material 3 | 页面、颜色组件、候选预览和交互 |
| 路由 | Navigation Compose | 页面导航、参数与返回栈 |
| 状态 | ViewModel、StateFlow、Coroutines | 单向数据流、网络任务和恢复 |
| 网络 | Retrofit、OkHttp | REST、上传、任务轮询；重试遵守幂等约定 |
| 序列化 | kotlinx.serialization | 与 API 对齐的结构化模型 |
| 图片 | Coil | 作品缩略图、原图、缓存和蒙版 |
| 本地缓存 | Room | 按用户隔离的收藏、最近项目和缓存 |
| 设置 | DataStore | 非敏感偏好；不保存模型密钥 |
| 绘制与导出 | Compose Canvas、Android Bitmap/Canvas | 色卡、结构化页面、透明蒙版、PNG |
| 测试 | JUnit、Compose UI Test、仪器测试 | 状态、锁定、撤销、导航及真机 |

结构：Compose UI → ViewModel → Repository → API/Room。视图坐标由画布统一变换；颜色位置以图像归一化坐标表示，页面元素以画布逻辑像素表示。不要混用两类坐标。

图像以 sRGB 作为首版交换空间；保持数字色值，屏幕差异单独说明。输入颜色或蒙版来自算法结果，不让模型猜色号。PNG 导出与预览共用场景模型，避免两套布局漂移。

## 后端与 AI

Python 3.12、FastAPI、Pydantic 2、SQLAlchemy 2、Alembic、PostgreSQL 16。A 牵头架构与接口契约，负责应用入口、配置、路由和统一错误等公共框架；B 共同设计契约并负责业务 API、数据、契约发布与部署；C 负责后端算法与模型内部服务。A/B 共用同一工程，不重复搭建骨架。首版单实例开发服务配有上限的工作队列，CPU 图像处理在独立工作执行单元，不能阻塞 API。任务状态保存数据库，进程中断将运行中任务标记为失败并允许显式重试；横向扩容时再引入专用持久队列。

Pillow 做方向、ICC 与基本图片处理；OpenCV、NumPy、colour-science 负责采样、代表色、色差、蒙版和比例。scikit-learn 可用于聚类。用户点选与区域采样补充小面积强调色，不能单纯以全图最大聚类决定所有颜色。

千问多模态 API 负责画面语义、场景、解释和自然语言调整。固定服务端模型适配层，以结构化 schema 输出候选和变更；校验后渲染，用户确认后保存。JSON 格式正确不等于内容正确。

优先采用精选实例的标签和结构化检索；暂不为小规模作品库增加独立向量数据库。公开作品统计预计算，交互高亮及参数预览在端侧或缓存中处理，减少重复模型请求。

账户密码采用成熟密码哈希库，访问令牌由服务器签发；用户资源做所有权校验。Web 与 Android 访问令牌仅保存在内存，首版重启后重新登录，不将令牌放入明文日志。后续持久登录需通过 Android Keystore 保护方案评审后再加。

## 版本固定策略

- Python 固定 3.12，PostgreSQL 固定主版本 16；部署再固定经过验证的镜像补丁或摘要。
- Android 使用稳定 Android Studio，JDK 17 作为初始候选，最终以选定 AGP 兼容表为准；计划 minSdk 26、compileSdk/targetSdk 36，初始化时核对插件与安装 SDK。
- Kotlin、AGP、Gradle Wrapper、Compose BOM 与库版本由 D 在 D1 选择一套兼容组合，写入 `libs.versions.toml` 和 Wrapper 并实际构建；本文不虚构已验证的版本组合。
- 后端直接依赖清单见 `backend/requirements.txt`，是待锁定选型范围；D1 在隔离环境解析并生成经过验证的锁定文件。当前不声称可复现应用构建。
