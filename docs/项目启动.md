# PuppleTrouble 项目启动

本页介绍启动顺序、入口、停止和排障。命令默认在 Windows PowerShell、仓库根目录执行；相对路径均以仓库根目录为准，而非 docs 目录。初次工具安装和完整参数见[环境配置说明](环境配置说明.md)。

## 1 当前实际能启动什么

当前只有文档、配置样例和后端依赖清单，尚无 Web package.json、后端 app/main.py、数据库迁移或 Android Gradle 工程。**目前可启动开发数据库；业务后端、Web 和 Android 的命令要等对应代码建立后才能运行。** 不将数据库启动成功当作整套应用已启动。

| 组件 | 当前状态 | 未来本地入口 |
|---|---|---|
| PostgreSQL | 有 Compose 配置；需要本机 Docker 引擎 | 127.0.0.1:5432，仅开发本机 |
| 业务后端 | 待 B/C 实现 | http://127.0.0.1:8000/api/v1 |
| API 交互文档 | 待后端建立后生成 | http://127.0.0.1:8000/docs |
| Web | 待 A 初始化工程 | http://localhost:5173 |
| Android | 待 D 初始化工程 | 模拟器或实体手机 |

## 2 第一次准备

先按[项目协作](项目协作.md)拉取最新代码，确认安装 Git、Docker Desktop、Python 3.12；Web 需要 Node.js 22（至少 22.12）；移动端需要 Android Studio 与相容的 JDK/SDK。

```powershell
git status
Copy-Item -LiteralPath .env.example -Destination .env
```

复制只在 `.env` 不存在时执行，已有配置不要覆盖。编辑 `.env`：修改本地数据库密码，同步 DATABASE_URL；填写随机 JWT_SECRET；AI_MODE=mock 可用于明确标识的开发模拟，真实调用需配置 MODEL_API_KEY、MODEL_API_BASE_URL、MODEL_NAME 并改为 real。不要把服务器密钥放入前端 VITE_ 变量。

```powershell
docker compose --env-file .env -f compose.dev.yaml config --quiet
docker compose --env-file .env -f compose.dev.yaml up -d db
docker compose --env-file .env -f compose.dev.yaml ps
```

预期 db 最终处于 healthy；首次初始化需等待。可使用下列命令排查：

```powershell
docker compose --env-file .env -f compose.dev.yaml logs --tail 50 db
```

日志需自行去除敏感配置后再分享。配置检查仅验证格式，不表示镜像下载、容器或数据库已经运行。

## 3 后端建立后的启动

以下步骤以 B 已提交 backend/app/main.py、设置模块、迁移、锁定依赖为前提。当前 requirements.txt 是待验证的直接依赖范围，尚非锁定文件。C 的算法和 AI 模块由后端加载，不另起一套外部 API。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

venv 仅初次创建；后续启动复用。实现设置模块时必须从仓库根目录显式加载 `.env`。迁移运行前核对目标数据库，种子作品导入由 B/C 提供明确命令和授权台账，不能假设库中已存在素材。

另开终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
```

按[接口文档](接口文档.md)注册并登录后使用业务接口；目前没有内置演示账户。`/health` 只说明存活，不证明 AI、资料库和所有业务均可用。

## 4 Web 建立后的启动

以 A 已提交 frontend/package.json、package-lock.json 和约定脚本为前提。第一次复制配置：

```powershell
Copy-Item -LiteralPath frontend/.env.example -Destination frontend/.env.local
```

已有文件不覆盖。开发地址为 `VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1`；后端 CORS_ORIGINS 允许实际使用的 localhost/127.0.0.1:5173。

另开终端进入 frontend 后执行：

```powershell
Set-Location frontend
npm ci
npm run dev
```

浏览器打开终端给出的地址。端口被自动改为其他值时，要么恢复 5173，要么同步后端 CORS。日常只在依赖变化时重新 npm ci。`npm run build` 生成 dist 发布产物；生产以静态服务器加 API 反向代理部署，不使用 Vite dev server。

## 5 Android 建立后的启动

以 D 已提交 android 工程、Wrapper、API 地址读取和 debug 网络策略为前提。Android Studio 打开 android 目录并同步。开发机 local.properties 保留 SDK 路径，并加入：

```properties
API_BASE_URL=http://10.0.2.2:8000/api/v1/
```

这是模拟器访问电脑的地址。USB 真机可使用：

```powershell
adb devices
adb reverse tcp:8000 tcp:8000
```

USB 真机 API_BASE_URL 改为 `http://127.0.0.1:8000/api/v1/`，重建或刷新对应配置。普通局域网真机需要后端显式监听局域网并限制防火墙范围；仅在有此需求时使用 0.0.0.0，不作为默认启动方式。

Android Studio 选择设备点击 Run；或从 android 目录执行 `./gradlew.bat assembleDebug`，以实际工程输出为准。原生 App 完成颜色浏览、拍照取色、作品高亮和配色预览，不依赖 Web 编辑器进程。

## 6 每日启动与停止

正常顺序是：Docker 引擎 → db → 后端 → Web 和／或 Android。开发数据库已存在时 `up -d db` 会复用数据卷；应用重启后按首版约定重新登录。

启动后联合检查：浏览一个作品 → 高亮一种颜色 → 创建项目 → 请求候选 → 确认保存 → 重开项目。mock 只验证联调，真实 AI 应另外检查来源和效果。

停止顺序：先停客户端或 Web，后端终端 Ctrl+C，最后按需停止数据库：

```powershell
docker compose --env-file .env -f compose.dev.yaml stop db
```

stop 保留容器和数据。`down` 删除容器但默认保留命名卷；不随手添加 `-v`。不启动容器也可以阅读文档，但不能运行数据库相关业务。

## 7 常见阻塞

| 现象 | 优先检查 |
|---|---|
| Docker 连接失败 | Docker Desktop／引擎是否运行，Compose 能否连接 |
| 找不到 package.json、main.py 或 Wrapper | 当前是否仍是文档阶段；拉取对应成员已提交的实际工程 |
| 数据库密码错误 | .env 与 DATABASE_URL 一致；旧数据卷密码不会随环境变量自动更新 |
| Web 跨域或图片无法导出 | API 地址、CORS、认证图片加载和字体是否可访问 |
| Android 连不上服务 | 模拟器 10.0.2.2／USB reverse、debug HTTP 策略、地址配置是否重新生效 |
| 模型不可用 | AI_MODE、服务端 key／地址／型号、配额和超时；保留项目原版本 |
| 网页修改看不到 | 前端项目版本、缓存、已保存与草稿状态；冲突不覆盖他人改动 |

首次工程可启动后，各负责人必须按本页从新环境复跑并更新真实命令、锁文件和验证日期。当前仅声明配置语法检查，不预先声明完整启动成功。
