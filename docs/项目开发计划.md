# PuppleTrouble 项目开发计划

人员 4 人，2026 年 11 月 15 日开工，2026 年 12 月 14 日交付，共 30 个自然日。日期均为北京时间。11 月 9 日的文档准备不计入工期。

这是首版开发计划，不把“30 天”解释为每人连续全日投入。启动时确认各人实际可投入时间；如果课程占用较多，优先收缩辅助功能，不牺牲核心闭环与验证。

## 交付目标

Web 发布构建、可安装 Android APK、可部署业务服务、作品与颜色资料库、源码与依赖锁定、真实试用与测试记录、演示视频及参赛文档初稿。区域初赛截止为 2027-01-15 18:00，本计划不占用之后的完善时间作为默认工期。

核心闭环：浏览颜色 → 查看真实作品中的颜色区域和解释 → 应用到单页模板 → 自然语言局部修改 → 锁定与撤销 → 保存和复用项目风格 → 导出。

## 功能优先级

| 级别 | 范围 | 交付要求 |
|---|---|---|
| P0 | 色系浏览、色号、作品详情和颜色高亮 | 可重复的取色结果；来源可追溯；高亮阈值可调整 |
| P0 | 颜色角色映射、2～3 个结构化模板、候选预览 | 背景、文字、强调色清晰；可比较、锁定、撤销 |
| P0 | AI 理解与局部配色修改 | 保留锁定项；输出受校验；失败不破坏项目 |
| P0 | 收藏、项目版本、偏好范围、PNG/JSON 导出 | 重启可恢复；账户隔离；旧版本可回看 |
| P1 | 风格筛选、相近色、更多作品、简易图表配色 | 核心闭环稳定后完善 |
| P2 | 更多字体形状建议、CSS 导出 | 允许递延；不影响 P0 验收 |

不在首版承诺中加入任意 PPTX 往返编辑、通用网页编辑器、印刷校色和自训练大模型。精选作品以 40～60 件为目标，先保证约 20 件审核完成的可演示资料；新增数量不能替代质量。

## 日程与验收

A 为 Web 前端，B 为后端兼数据库，C 为后端兼算法，D 为 Android 移动端，岗位不变。下表是计划任务而非完成记录；每项工作当日应留下对应 PR、可运行样例或文档证据。

### 每人负责的目录和交接物

| 成员 | 计划模块位置 | 固定交接要求 |
|---|---|---|
| A | frontend/src 的页面、状态、API 封装和画布 | 组件／页面、交互截图、状态样例、Web 测试与导出 |
| B | backend/app/api、models、schemas、services 与 migrations | 契约、迁移、样例请求、权限和异常测试、部署说明 |
| C | backend/app/algorithms、ai、knowledge；data/catalog | 可重复的输入输出、算法版本、阈值、模型来源、误例与资料台账 |
| D | android/app 的 UI、ViewModel、Repository 与图形模块 | APK、真机记录、API 映射、原生预览与状态恢复测试 |

这些路径是待建工程的模块约定。A/C/D 不自行另建外部服务或数据库；B 为外部接口负责人。每天开始看前一日交接；依赖未完成时使用带 mock 标识的固定样例，不声称真实联通。

### 每日交接格式和依赖处理

每天同步：今天任务及链接、实际验证结果、遗留问题、明天需要谁提供什么。主责成员在任务 PR 写“完成条件”，未通过不得只标“已写代码”。文档／接口／样例变更随功能一并提交。

关键依赖为：B/C 的统一数据与蒙版 → A/D 展示；C 的候选 → B 校验任务 → A/D 比较和确认；B 的项目版本 → 两端保存与恢复。接口未就绪时先根据契约开发并标识 mock；从 D10 起核心里程碑必须用真实接口验收。

若前一日依赖延误，先完成不依赖它的界面状态、契约测试或误例整理；A 汇总影响并调整范围，不能假装联调完成。P0 风险优先于 P1/P2。每轮验证使用固定样例，新增失败样例进入回归集。

## 研究与反馈安排

前期只确定使用任务与可验证假设，不虚构用户结论。正式访谈和试用从 D15 左右开展，符合中后期反馈安排；初期建议 5～8 名目标用户完成相同任务，保留同意、问题与修改记录。样本数量是计划，不是完成情况。

对照普通色卡选择或图片取色，观察完成时间、有效修改次数、参考配色是否易于应用、解释是否帮助选择。审美偏好保留主观性，不用一个总分宣称客观优劣。

## 质量与交付门槛

- 核心用例覆盖颜色匹配、锁定不变、候选不自动保存、版本冲突、撤销、模型超时、账户隔离。
- 至少一台实体 Android 手机完成关键流程；Web 在桌面 Chrome/Edge 验证画布与导出，另外检查模拟器和不同屏幕尺寸。
- 色值往返转换使用固定测试图与容差，解释与实际蒙版、来源逐项核对。
- 延迟、上传量、资源占用和调用成本记录真实结果；D3 确定设备、网络与可接受预算，不预填未经测试的性能数字。
- 无密钥、个人资料或未授权素材进入 Git；参赛评审副本另做匿名核对。

若核心识别不稳，保留用户点选和阈值调整；若 AI 不稳，提供明确标注的规则候选和错误提示，不能伪称 AI 已完成。延期风险先递延 P2、减少模板和作品扩充，保留核心闭环、测试与文档。
