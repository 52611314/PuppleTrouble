# 数据库环境配置

主责 B。返回[环境配置入口](../环境配置说明.md)，启动见[项目启动](../项目启动.md)。命令从仓库根目录执行；修改前先阅读[HANDOFF](../HANDOFF.md)。

## 工具和配置

安装并运行 Docker Desktop，确认包含 Compose。采用 PostgreSQL 16；镜像补丁或摘要在实际验证后固定。当前 compose.dev.yaml 只有开发数据库服务，没有业务后端容器。

仅首次复制 `.env.example` 为 `.env`，修改 POSTGRES_DB、POSTGRES_USER、POSTGRES_PASSWORD，并同步 DATABASE_URL。主机后端使用 `127.0.0.1:5432`；未来后端也进入 Compose 网络才使用服务名 db。数据库不直接对 Web 或手机开放。

DATABASE_URL 形式为 `postgresql+psycopg://<用户>:<编码后的密码>@127.0.0.1:5432/<数据库>`；尖括号是占位说明。密码中的特殊字符需 URL 编码，不能将真实密码写入文档。

## 当前可执行的数据库准备

配置完成、Docker 引擎运行后执行：

```powershell
docker compose --env-file .env -f compose.dev.yaml config --quiet
docker compose --env-file .env -f compose.dev.yaml up -d db
docker compose --env-file .env -f compose.dev.yaml ps
docker compose --env-file .env -f compose.dev.yaml logs --tail 50 db
```

预期 db 最终 healthy，首次初始化需等待。config 只检查格式，不能证明镜像下载、容器或数据库已运行；日志去敏后再分享。

## 停止与故障处理

```powershell
docker compose --env-file .env -f compose.dev.yaml stop db
```

stop 保留容器和数据；down 删除容器但默认保留命名卷，不随意添加 -v。更改 `.env` 密码不会自动修改已经初始化的数据卷账户，需要数据库命令调整；重建前先明确保留和备份数据。

端口冲突时调整 compose.dev.yaml 的主机映射，并同步 DATABASE_URL。默认仅绑定 127.0.0.1:5432，不为手机连接而暴露数据库。
