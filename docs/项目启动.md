# PuppleTrouble 项目启动

本文用于 Windows PowerShell 的首次配置与日常启动。后端、Web、Android 工程均已建立，不再需要生成工程。当前实现为运行检查、数据库初始迁移与两端连接检查首页；登录、取色、作品、编辑、AI、保存与导出等业务按计划开发，预留空文件不能运行出这些功能。

## 1 路径和运行约定

项目根目录是包含 README.md、backend、frontend、android 和 compose.dev.yaml 的 PuppleTrouble 目录。各终端开始前先切换到自己的项目根目录；下文相对命令均以该目录为起点。

可在文件管理器中打开项目根目录，右键选择“在终端中打开”；也可使用 Set-Location 切换到自己的项目目录。

后端使用根目录 `.venv`，配置统一读取根目录 `.env`，即使在 backend 路径启动也不改变配置来源。Web 使用 frontend/.env.local，Android 使用 android/local.properties；所有配置均由团队自行完成本机设置，不按成员分配。

## 2 首次配置：只需做一次

### 2.1 准备工具

- Python 3.12、Node.js 22.12 以上、Git。
- Docker Desktop 与 Compose，先打开 Docker Desktop，等待引擎可用。
- Android Studio、JDK 21、Android SDK Platform 36、Build Tools 35.0.0、Platform Tools；模拟器另需系统镜像和 AVD。工程输出 Java 17 字节码，构建机用 JDK 21。

配置细节见[环境配置说明](环境配置说明.md)。不要复制其他项目的环境名、数据库名、端口或分支；本仓库沿用 main 加任务分支的约定。

### 2.2 生成本地配置

在项目根目录执行：

```powershell
.\scripts\setup-local.ps1
```

脚本首次生成根目录 .env 的随机数据库密码及 JWT_SECRET，复制 Web 公开配置，并尝试找到 Android SDK。已有配置全部保留，不覆盖。若提示找不到 SDK，使用自己的实际路径再执行：

```powershell
.\scripts\setup-local.ps1 -AndroidSdk "$env:LOCALAPPDATA\Android\Sdk"
```

SDK 装在其他位置时替换该参数。脚本不安装依赖、不启动服务；如果 PowerShell 策略阻止脚本，可按下列等效调用只为当前进程放行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-local.ps1
```

AI 模型暂不影响启动，无需提供真实 key。后续真实模型开发再配置 MODEL_API_KEY／MODEL_API_BASE_URL／MODEL_NAME；当前没有已实现的 AI 调整接口，AI_MODE=mock 也不会生成模拟业务。

### 2.3 配置 Python 与后端依赖

确认用于创建环境的解释器为 Python 3.12：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
```

若电脑默认 Python 不是 3.12，先安装 Python 3.12，再使用其解释器路径或 `py -3.12 -m venv .venv`。后续命令显式调用 .venv，无需激活环境，也不依赖 Conda 环境名。锁文件面向 Windows／Python 3.12；依赖范围见 requirements.txt。

### 2.4 安装 Web 依赖

```powershell
Set-Location frontend
npm ci
Set-Location ..
```

使用 package-lock.json，不重新生成脚手架。Android 在首次执行 Wrapper 或 Android Studio 同步时解析依赖，无须本机单独安装 Gradle。

### 2.5 启动数据库并迁移

从根目录执行：

```powershell
docker compose --env-file .env -f compose.dev.yaml up -d --wait db
docker compose --env-file .env -f compose.dev.yaml ps
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini current
```

等待 db 为 healthy 再迁移。当前 revision 为 `0001_initial_users`，创建 users 表；不创建默认应用账号或作品。数据库名和开发连接用户名默认均为 puppletrouble，主机地址为 127.0.0.1:5678，容器内 PostgreSQL 同样监听 5678，密码取根目录 .env。端口与连接配置见[环境配置说明](环境配置说明.md#数据库连接与端口调整方案)。

## 3 日常启动：后端

先打开 Docker Desktop；在终端 1 的项目根目录启动数据库：

```powershell
docker compose --env-file .env -f compose.dev.yaml up -d --wait db
```

终端 2：切换到自己的项目根目录，再进入后端并启动：

```powershell
# 先切换到自己的 PuppleTrouble 项目根目录
Set-Location backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

保持该终端打开。若已在根目录，也可使用以下等效命令：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

另开终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health/ready
```

health 返回 data.status=ok；ready 返回 ready、database=connected 和迁移版本。数据库或迁移未就绪时 ready 返回 503；health 成功不代替数据库就绪。接口文档为 http://127.0.0.1:8000/docs ，机器可读契约为 /openapi.json，目前只列已实现的运行检查。

修改根目录 .env 后手动重启后端；不能保证 reload 监听配置文件变化。

## 4 日常启动：Web

终端 3：

```powershell
# 先切换到自己的 PuppleTrouble 项目根目录
Set-Location frontend
npm run dev
```

打开 http://127.0.0.1:5173 ，启动首页应显示“后端连接正常”。未启动后端或请求超时会结束加载、提示断连，并提供重新检查按钮。本地示例色卡用于首页展示，不是取色结果。

开发服务器固定 5173，端口占用直接报错，不自动换端口。API 地址在 frontend/.env.local 的 VITE_API_BASE_URL，修改后重启 Vite。生产构建与本地预览：

```powershell
npm run build
npm run preview
```

预览地址 http://127.0.0.1:4173 。生产发布时由静态服务器托管 dist 并将 /api/v1 反向代理至后端，不使用 Vite 开发服务。

## 5 日常启动：Android

### 模拟器方式

Android Studio 打开仓库的 android 目录，Gradle JDK 选择 JDK 21，同步后从 Device Manager 启动一个 AVD。android/local.properties 包含本机 sdk.dir 和：

```properties
API_BASE_URL=http://10.0.2.2:8000/api/v1/
```

10.0.2.2 指向开发电脑，不能用模拟器自身的 localhost 替代。后端与数据库保持运行，点击 Android Studio 的 Run；也可在新终端构建、安装：

```powershell
# 先切换到自己的 PuppleTrouble 项目根目录
Set-Location android
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:installDebug
```

再从模拟器桌面打开“玩犊紫”。命令行启动可使用 SDK Platform Tools 中的 adb（以下以 adb 已加入 PATH 为例）：

```powershell
adb devices
adb shell am start -W -n com.puppletrouble.app/.MainActivity
```

有多台设备时给 adb 加 `-s 设备序列号`，或给 Gradle 设置相应设备选择。debug APK 为 `android/app/build/outputs/apk/debug/app-debug.apk`。首页连接成功后显示服务名及版本；失败可重试，不代表已实现产品功能。

### USB 真机方式

开启开发者选项和 USB 调试并授权电脑；将本机 android/local.properties 的 API_BASE_URL 改为 `http://127.0.0.1:8000/api/v1/`，然后执行：

```powershell
adb devices
adb reverse tcp:8000 tcp:8000
```

重新构建并安装 debug APK，地址在构建期读取，修改后必须重建。HTTP 仅 debug 允许；release 用 HTTPS，并需传 `-PRELEASE_API_BASE_URL=https://实际服务/api/v1/`，占位地址不能原样使用，发布签名另行配置。当前交付的是用于开发的 debug APK。

## 6 只在相关文件变化后执行

| 变化 | 从哪个路径执行 | 命令 |
|---|---|---|
| 后端锁文件 | 根目录 | `.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt` |
| Web package-lock.json | frontend | `npm ci` |
| 数据库迁移 | 根目录 | `.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head` |
| Gradle／Android 依赖 | android | Android Studio 同步，或 `.\gradlew.bat :app:assembleDebug` |
| .env／客户端 API 地址 | 对应终端 | 重启后端／Web；Android 地址变化后重建 |

不需要每天重建虚拟环境、重装依赖或生成工程。HANDOFF 现阶段为空，暂不填写；Git 拉取与简体中文提交规范见[项目协作](项目协作.md)。

## 7 验证、停止与排障

在根目录检查后端测试：

```powershell
.\.venv\Scripts\python.exe -m pytest -c backend/pytest.ini
```

Web 在 frontend 执行 `npm run test`；后端运行时执行 `npm run test:e2e`，端到端配置使用 Microsoft Edge，运行前需安装该浏览器；也可调整 Playwright 的 channel 并安装对应浏览器。

停止时关闭 App／模拟器，后端和 Web 终端 Ctrl+C；数据库按需保留或停止：

```powershell
docker compose --env-file .env -f compose.dev.yaml stop db
```

stop 保留数据，不随意使用 down -v。更换 .env 密码不会自动更新已有数据库卷的账户密码，应先备份并用数据库命令调整。

| 问题 | 检查方式 |
|---|---|
| Docker engine 连接失败 | 打开 Docker Desktop，等待引擎启动后重试 |
| ready 返回 503 | 检查 db healthy、根目录 .env 的连接及密码，执行迁移 |
| 找不到 Python 模块 | 使用根目录 .venv，确认依赖已装，按上述相对路径启动 |
| Web 连接失败 | 后端 8000、VITE_API_BASE_URL、根目录 CORS_ORIGINS 与实际 Web 来源 |
| 8000／5173 被占用 | 先确认占用进程用途，不停止无关服务；改端口需同步客户端和 CORS |
| SDK/JDK 错误 | local.properties 的真实 SDK 路径、SDK 36／Build Tools 35.0.0、JDK 21 与 JAVA_HOME |
| Android 无法连接 | 模拟器 10.0.2.2；USB 真机 reverse 与重新构建；debug HTTP 配置 |
| Gradle 下载失败 | 确认网络能访问 Google Maven、Maven Central 和 Gradle 分发；使用 Wrapper，不换成本机任意 Gradle |
