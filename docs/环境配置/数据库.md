# 数据库环境配置

所有成员自行配置本机环境。返回[配置入口](../环境配置说明.md)，完整步骤见[项目启动](../项目启动.md)，实体与约束见[数据库设计](../数据库设计.md)。

## 参数

运行 Docker Desktop 和 Compose。项目使用 postgres:16，本机只绑定 127.0.0.1:5432，库名和用户名为 puppletrouble；密码由 scripts/setup-local.ps1 在根目录 .env 中随机生成。不要使用其他项目的库名、5433 等端口或已有账号。

主机上的后端使用 DATABASE_URL 中的 127.0.0.1；只有未来后端也进入同一 Compose 网络才使用服务名 db。目前 Compose 只有 db 服务。私人密码不写进文档或 Git。

## 启动与迁移

从根目录执行：

```powershell
docker compose --env-file .env -f compose.dev.yaml config --quiet
docker compose --env-file .env -f compose.dev.yaml up -d --wait db
docker compose --env-file .env -f compose.dev.yaml ps
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini current
```

等待 db 为 healthy 再迁移。当前只有 0001_initial_users，创建 users 结构，不导入账号或作品。后续新迁移按模型变更生成，不在扫描目录放空迁移。检查 /api/v1/health/ready 是否 ready，不只看容器进程存在。

## 保留数据与排障

日常停止用 `docker compose --env-file .env -f compose.dev.yaml stop db`。down 默认保留命名卷，不随意添加 -v。改 .env 密码不会更新旧卷账号，需先备份并用数据库命令修改；端口冲突先确认占用用途，改映射时同步 DATABASE_URL。

日志使用 `docker compose --env-file .env -f compose.dev.yaml logs --tail 50 db`，去敏后再分享。计划中的 backup-db.ps1／restore-db.ps1 目前为空，尚不能用于备份或恢复；正式实现与验证安排在 D21 前。
